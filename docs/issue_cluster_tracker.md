## 10.9 修复5改签场景行李延误计算修正 + receipt_source 放宽

**文件**:
- `app/modules/baggage_delay/stages/calculator.py`

**根因**（3个独立bug）：

### Bug 5A：改签场景 alternate 基线错误

改签场景下，calculator 使用 `alternate.alt_arr`（改签航班到达时间）作为"行李应运抵"时间点。但对于改签旅客，行李应随同旅客搭乘改签航班，因此正确的比较基线应为 **改签航班起飞时间**（`alt_dep`），而非到达时间。

**修复**：当 `alternate.is_connecting_rebooking=true` 时，优先使用 `alt_dep`（改签航班起飞时间）作为行李应到达时间基线，`arrival_time_source` 标记为 `alternate_departure`。

### Bug 5B：alternate 到达时间与签收时间重复

Vision 模型在某些情况下将行李签收时间同时填入 `alternate.alt_arr`，导致 calculator 计算 `alt_arr - baggage_receipt_time = 0`。

**修复**：当 `alternate.alt_arr` 与 `baggage_receipt_time` 完全相同时，舍弃 alternate 到达时间，回退到原航班到达时间。

### Bug 5C：改签场景 receipt_source 过严

当 `baggage_receipt_time_source=unknown` 时，calculator 拒绝使用签收时间。但对于改签场景，AI 从文本中解析出的签收时间应被接受（因为转运航班到达时间本身就是一种间接签收时间）。
