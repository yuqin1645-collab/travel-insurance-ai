## 案件 1: a0nC800000Ogop0IAB（航班延误）

### 基本信息
- **航班**: BA2611 CTA(卡塔尼亚)→SXF(柏林)，联程至 HKG(香港)
- **保单有效期**: 2026-04-30 ~ 2026-05-09
- **AI**: 通过，延误23h21m，赔付600元
- **人工**: 拒绝

### 人工拒绝原因
1. BA2611 起飞延误4小时23分钟，到达延误3小时41分钟，**未达5小时起赔标准**
2. **中转接驳免责**：原预定的接驳航班（BA31）因第一程延误无法搭乘，后续中转造成的延误不予赔付

### AI 判定链路
```
Vision 提取:
  - 原航班 BA2611: CTA→SXF (延误证明显示延误4h23m)
  - 原航班 BA31: LHR→HKG (第二程)
  - 改签后 CX252: LHR→HKG (5月9日)
  - schedule_revision_chain 全部时间为 "2026-05-08 00:00/unknown" ← 关键问题！

AI 计算:
  first_planned_arr_utc: 2026-05-08T00:00:00+00:00  ← 错误！这是行程单的占位时间
  alt_arr_utc:           2026-05-08T23:21:00+00:00
  计算延误: 1401分钟(23h21m) → 通过
```

### 根因: **延误计算基准错误**

AI 的 `computed_delay` 方法使用了"行程签名(前序段)-取max(起飞延误,到达延误)"的逻辑，但关键问题是：

1. **Vision 提取的 `schedule_revision_chain` 全部时间为 `2026-05-08 00:00/unknown`**，不是真实计划时间
2. AI 回退使用了 `aviation_scheduled` 的时间(16:10→18:25)，但这已经是延误后的时间
3. 最终计算时，`first_planned_arr_utc` 被设为 `2026-05-08T00:00:00+00:00`（占位值），导致计算出的延误严重偏大

**正确的延误应该是**：延误证明明确记录了起飞延误4h23m、到达延误3h41m，均未达5小时标准。

### 修复方向
- `computed_delay` 方法应优先使用延误证明中明确记录的延误时间，而非回退到基于航班时间计算的差值
- 当中转接驳场景中 Vision 未能提取到准确的 first_planned 时间时，应使用延误证明上的延误时长
- 中转接驳免责的 `rebooking_override` 逻辑过于宽泛：原航班取消+改签≠中转接驳免责

## 案件 3: a0nC800000OUo3DIAT（行李延误）

### 基本信息
- **航班**: OS16 (奥地利航空)
- **AI**: 需补齐资料（转人工，handwritten标记）
- **人工**: 拒绝
- **保单赔付**: 1000元（人工原赔付记录）

### 人工拒绝原因（两条）
1. **航班延误部分**：OS16 起飞延误31分钟，到达延误55分钟，**未达5小时起赔标准**
2. **行李延误部分**：旅客通过铁路等交通方式提前到达目的地并提取行李，**不在权益保障范围内**

### AI 判定链路
```
Vision 提取 (00_vision_extract.txt):
  delay_hours: 16.0  ← 从 PIR 报告提取的"行李延误16小时"
  baggage_delay_proof: true (PIR报告)

baggage_delay_parse:
  delay_hours: 16
  但无签收时间(receipt_time)

vision_merge:
  → 无签收时间 → 转人工审核
  AI备注: "转人工审核，存在不可识别的字段"
```

### 根因: **行李延误签收时间缺失 + 延误计算未对齐**

1. **AI 提取了 PIR 报告上的 delay_hours=16**，但行李延误需要**签收时间**作为计算基准（行李应到达时间 vs 实际签收时间）
2. **无签收时间** → pipeline 无法完成延误时长计算 → 降级为"需补齐资料"转人工
3. **人工审核角度**：
   - 如果行李是旅客通过铁路提前到达目的地后自行提取（非机场投递），则不属于行李延误险保障范围
   - 人工用的是航班到达延误时间（55分钟）来判断，远未达6小时门槛

### 修复方向
- `calculator.py` 中当无签收时间但有 PIR delay_hours 时，应明确拒绝而非补件：如果 PIR 报告上记录行李延误时长但未提供签收时间，且旅客已通过其他方式（铁路等）提前到达并提取行李，应直接判定为除外责任
- 新增"旅客提前自行提取行李"的除外责任检测

## 总结

| 案件 | 根因 | 修复优先级 | 预估影响范围 |
|------|------|-----------|-------------|
| Ogop0IAB, OgpmfIAB | 延误计算使用了错误的 first_planned 基准（占位时间） | P1 | 中转改签类案件 |
| OUo3DIAT | 无签收时间时降级补件，未识别"旅客提前自行提取行李"除外情形 | P2 | 行李延误类案件 |

### 根本问题
1. **`computed_delay` 方法的回退逻辑缺陷**：当 Vision 无法提取准确的 first_planned 时间时，回退计算会严重偏离实际延误时长
2. **中转接驳豁免逻辑过于严格**：原航班取消+改签→被判定为中转接驳免责，但实际上旅客确实是因航班延误导致的行程变更
3. **行李延误无签收时间的处理缺失**：应区分"无法获取签收时间（需补件）"和"旅客已提前提取行李（除外责任）"
