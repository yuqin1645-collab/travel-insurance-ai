## BL-BAG-001：行李丢失 vs 行李延误的边界判定

**影响案件数**：12件（P2中"事故类型为行李丢失"类别）
**ForceID示例**：a0nC800000IREu9IAH, a0nC800000Ih7S6IAJ, a0nC800000IpF2gIAF

### AI代码/prompt逻辑

```python
# pipeline.py:285-310（修复后）
# 关键区分：行李是否最终找回。有有效签收时间=已找回=延误，无签收时间=永久丢失=丢失
has_receipt_time = bool(raw_receipt) and _parse_dt_flexible(str(raw_receipt)) is not None
has_calculable_delay = delay_calc.get("delay_hours") is not None

if baggage_loss and not has_receipt_time and not has_calculable_delay:
    # 真正永久丢失 → 转随身财产
    return reject
elif baggage_loss and (has_receipt_time or has_calculable_delay):
    # 曾报丢失但已找回 → 按延误处理
    ai_parsed["accident_type"] = "baggage_delay"  # 注入修正值
```

### 人工结果

人工对大部分此类案件的处理：**赔付**（按行李延误通过）

### 业务逻辑推测

**核心区别：行李是否最终找回**

| 维度 | 行李延误 | 行李丢失 |
|------|---------|---------|
| 定义 | 行李未在合理时间内送达，但最终找回 | 行李永久失踪，确认无法找回 |
| 理赔条件 | 延误≥6小时 | 按随身财产损失理赔 |
| 关键证据 | 有行李签收时间/证明 | 无签收记录，航空公司确认丢失 |

### 修复方案（已实施）

修改了3处：
1. **pipeline.py:285-308**：事故类型检查增加"行李是否找回"判断
2. **pipeline.py:299-302**：注入修正后的 accident_type 到 ai_parsed
3. **prompts/baggage_delay/02_audit_decision.txt:28-31**：prompt增加"行李已找回按延误处理"规则

### 修复效果

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 行李丢失类P2 | 12件 | 3件 |
| 行李延误整体一致率 | 74.5% | 78.0% |

### 剩余3件分析

| ForceID | AI | 人工 | 分析 |
|---------|-----|------|------|
| a0nC800000IuhPiIAJ | 拒绝(丢失) | 通过(1000元) | baggage_receipt_time=unknown, delay_hours=None，**真正丢失**。但人工赔付，可能是业务宽松或有额外材料 |
| a0nC800000JFeYnIAL | 拒绝(丢失) | 需补齐资料 | 同上，真正丢失。人工要求补件而非直接拒赔 |
| a0nC800000IREu9IAH | 需补齐资料 | 通过(1500元) | receipt_time已修正为baggage_delay，但AI仍要求补签收证明 |

这3件需要**业务方确认**：对于无签收记录但人工赔付的案件，AI是否应该放宽处理？

## BL-BAG-002：超30天未补件自动关案

**影响案件数**：13件（P0中"超30天未补件自动关案"类别）
**ForceID示例**：a0nC800000LWbYEIA1, a0nC800000HjxQLIAZ, a0nC800000I9NUTIA3 等

### AI代码/prompt逻辑

AI正常审核通过，建议赔付（如：延误48.83小时，建议赔付1000元）。

### 人工结果

人工备注："超30天未补件自动关案"或"保险公司要求的行李延误时数及原因证明材料（含签收时间）"

### 业务逻辑推测

**核心问题：业务流程限制，非AI审核逻辑问题**

旅客在提交理赔申请后，保险公司要求补充材料（如行李延误证明）。如果旅客在30天内未补齐材料，系统会自动关案（拒绝）。但AI审核时不知道这个业务流程状态，仍然按材料完整性进行了审核。

这是**业务流程层面的差异**，不是AI审核代码的bug。

### 建议

1. 在claim_info中增加一个字段标识"是否已超30天自动关案"
2. Pipeline中增加对此字段的检查，如已自动关案则跳过审核
3. 或者在数据同步时将此类案件标记为"业务流程排除"，不参与AI vs 人工一致性统计

### 业务逻辑推测

保单除外责任条款明确规定：行李被海关/政府部门没收、扣留、安检导致延误的，不属于保障范围。

这是合理的除外责任，AI应该识别并拒赔。

### 修复状态

- OEMMDIA5（P0真实案件）：已在之前的修复中增加 Description_of_Accident 的硬除外关键词检查
- Lr24PIAR（P2）：AI已拒赔（海关没收/扣留），但人工通过 → 需确认是AI正确还是人工有误

### 如何与业务方沟通

> 关于海关没收/扣留导致的行李延误：
>
> 保单条款明确将此列为除外责任。AI系统已能识别此类情形并拒赔。
> 但发现1件案件（a0nC800000Lr24PIAR）AI拒赔但人工通过，需确认：
> 1. 该案件是否确实涉及海关没收/扣留
> 2. 人工通过是否有特殊理由（如材料重新补充、条款解释差异等）

## BL-BAG-004：纯国内航班但含国际行程

**影响案件数**：8件（P2中"纯国内航班"类别）
**ForceID示例**：a0nC800000IUIrbIAH（北京→南京）, a0nC800000IWp9vIAD（北京→上海）

### AI代码/prompt逻辑

```python
# handlers.py:_check_domestic_flight
if dep_country == "中国" and arr_country == "中国":
    # 检查是否有出入境记录
    exit_dt = vision_extract.get("exit_datetime") or claim_info.get("First_Exit_Date")
    if exit_dt and str(exit_dt).strip().lower() not in ("", "unknown"):
        return None  # 有出入境记录，豁免
    return "拒赔：航段为国内航班..."
```

### 人工结果

人工：**通过**（赔付）

### 业务逻辑推测

旅客的实际行程是：国际联程（如 纽约→上海→南京），但理赔材料中只提供了国内段（上海→南京）的行李延误证明。

**业务处理方式**：
- 旅客有出入境记录 → 说明确实有国际行程
- 国内联程段的行李延误也在保障范围内
- 人工审核看到出入境记录后直接通过

### 修复状态

**已修复**。代码中已有出入境记录兜底逻辑。重跑验证显示此类案件现在AI也判定为通过。

## BL-BAG-005：延误未达6h门槛 — PIR创建时间 vs 实际送达时间

**影响案件数**：20件（P2最大子类）
**ForceID示例**：a0nC800000IBb0IIAT, a0nC800000IEFfxIAH

### AI代码/prompt逻辑

行李延误计算公式：
```
延误时长 = 行李实际签收时间 - 行李应到达时间
```

签收时间来源优先级：
1. Vision从材料中提取的明确签收时间
2. 转运航班到达时间（代理）
3. PIR报告中的时间

### 问题

部分案件中，Vision提取的"签收时间"实际上是**PIR（Property Irregularity Report）创建时间**，而非行李实际送达时间。PIR创建时间通常远早于实际送达时间，导致计算出的延误时长偏短（<6小时）。

### 人工结果

人工通过，说明人工使用了更准确的签收时间，或对材料有不同的理解。

### 需要确认

1. 这是一个**Vision prompt优化**问题，需要提高Vision对"行李签收时间"的识别精度
2. 区分PIR创建时间和行李实际送达时间
3. 建议沟通业务方确认：当只有PIR报告时，应以哪个时间为准？

## BL-BAG-006：超出保单有效期 — 安联顺延规则

**影响案件数**：8件
**ForceID示例**：a0nC800000IF28pIAD, a0nC800000IhYvNIAV

### AI代码/prompt逻辑

```
实际到达时间: 2026-02-22 06:28
保单有效期: 2026-02-21 23:59
→ 超出有效期，拒赔
```

### 人工结果

人工：**通过**

### 业务逻辑推测

安联保单有**顺延规则**：如果旅行跨越保单有效期截止日，保单自动延延至旅行结束。AI的 `_check_actual_arrival_vs_policy` 已使用 policy_validity 模块返回的顺延后日期，但仍有8件被拒。

可能原因：
1. 顺延规则的适用条件有特定限制（如仅限航班延误导致的超期，不含行李延误）
2. 国际航班到达日天然超保单截止日，业务上通常放宽处理

### 需要与业务方确认

> 关于保单有效期顺延规则在行李延误场景的适用：
>
> 当前AI对8件案件判定为"超出保单有效期"拒赔，但人工审核通过。
> 这些案件的实际到达时间比保单截止日晚数小时至数十小时不等。
>
> **请确认**：
> 1. 安联顺延规则是否适用于行李延误场景？
> 2. 顺延后的截止时间如何计算？
> 3. 国际航班到达日超保单截止日，是否自动视为顺延？
>
> **影响范围**：约8件案件
