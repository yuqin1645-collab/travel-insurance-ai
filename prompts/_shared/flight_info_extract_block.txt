## 航班信息识别核心规则

### 航班号识别（高风险，必须逐字符核对）
航班号中的每一位数字都必须独立核对，绝对禁止根据上下文推断或"补全"任何一位数字。以下是高频混淆场景，必须特别注意：
- 末位数字混淆：QZ646 ≠ QZ648，MU5183 ≠ MU5188，CA1234 ≠ CA1235，数字 6/8、3/8、1/7 极易混淆
- 字母混淆：字母 O 与数字 0、字母 I 与数字 1、字母 B 与数字 8
- 若同一材料中出现多个相似航班号（如 QZ646 和 QZ648），必须全部列入 all_flights_found，绝对禁止合并或只保留其中一个
- 若图片中航班号被 logo、图标、折叠区域部分遮挡，必须在 extraction_notes 中注明"航班号存在遮挡，已尽力识别为 XXX，建议人工核查"

**Carrier Code 与 Flight Number 分开显示的登机牌（高频场景）**：部分登机牌将航空公司代码（CARRIER/AIRLINE）与航班号（FLIGHT/FLT NO）分列两栏，必须将二者拼接为完整航班号：
- 例：CARRIER: T5，FLIGHT: 444 → 完整航班号为 **T5444**
- 例：CARRIER: CZ，FLT: 380 → 完整航班号为 **CZ380**
- 绝对禁止只填数字部分（如 "444"），必须带上航空公司代码前缀

### 行程单与登机牌分开识别
行程单/电子客票上的航班号是"原定航班"，登机牌上的航班号是"实际乘坐航班"。若两者不同，说明发生了改签，必须将两个航班号都列入 all_flights_found，绝对禁止只保留其中一个。行程单上的原定航班即使已取消，也必须列出。

### 多张登机牌场景（高频遗漏场景，必须识别）
当材料中存在**多张登机牌**时（如原航班登机牌 + 改签后新航班登机牌），**每一张登机牌上的航班号和日期都必须独立提取并列入 all_flights_found**，绝对禁止只提取其中一张。

**日期是关键区分依据**：若一张登机牌的日期与原航班日期相同但航班号不同（如 U25270 vs EJU5270），另一张登机牌的**日期和航班号都与原航班不同**（如 2月9日 U24899），则后者才是改签后实际乘坐的航班。两张登机牌都必须列出，缺一不可。

**绝对禁止**：因为已经提取了一张登机牌的航班号，就跳过另一张日期不同的登机牌。每一张登机牌都是独立证据，必须逐张处理。

### 行程变动分区截图（高频场景，必须识别）
航旅APP（如携程、飞猪、去哪儿、Traveloka等）的行程变动通知截图中，常见"原航班/原定航班"与"行程变动后的新航班/新安排"两个分区并排显示。**两个分区的航班号必须全部列入 all_flights_found**，绝对禁止只提取其中一个分区的航班号。典型标志词：「原航班」「行程变动后的新航班」「新安排」「已变更」「原定」「更改为」等。

- **关键警告**：两个分区的航班号看起来相似时（如同为QZ64X），绝对禁止将两个分区的航班号归并为同一个。必须对每个分区的航班号独立逐字符核对后分别列出，即使末位数字只差1位（如QZ646 vs QZ648）也必须如实记录两个不同的航班号。

### 航空公司邮件/通知中的转运航班（行李延误案件关键场景）

在行李延误案件中，航空公司常通过邮件、短信或APP通知告知旅客行李的转运安排。**此类文件中提到的任何后续航班号都必须列入 all_flights_found**，即使该航班不是旅客本人乘坐的航班。行李通常会搭乘与旅客相同的后续航班运送，因此这些转运航班信息对计算行李延误时长至关重要。

典型标志词（多语言）：
- 中文："您的行李将搭乘..." / "行李预计到达..." / "后续航班" / "转运航班"
- 英文："Your suitcase will arrive on..." / "We've sent it on the next... flight" / "baggage will be forwarded on flight..." / "Your luggage will arrive on..."
- 其他语言中类似的行李转运表述

提取时：
- **source** 填 `airline_email`（航司邮件/通知/短信截图）或 `app_screenshot`（APP推送截图）
- **role_hint** 填写原文描述，如 "行李转运航班" / "baggage transfer flight" / "后续航班"
- 航班号必须逐字符核对，不可推断或补全

### 行李转运航班 vs 乘客实际乘坐航班（行李延误案件极易混淆场景）

**核心规则：flight_no 字段必须填旅客实际乘坐的末段航班，绝对禁止填行李转运航班。**

行李转运航班（baggage forwarding flight）是航空公司为了将迟到的行李运送到旅客所在地而安排的航班。**旅客本人可能已经离开，行李是单独托运的。** 行李转运航班的时间晚于旅客实际乘坐的航班，如果用行李转运航班作为计算基准，会严重低估延误时长。

如何区分：
- **乘客航班**：出现在登机牌、行程单、旅客本人的机票预订确认中
- **行李转运航班**：出现在航司邮件/通知中，描述为"您的行李将搭乘..." / "baggage forwarded on..." / "行李已装载" / "行李转运"
  - 此类航班的 role_hint 应填写原文描述（如 "行李转运航班"），供后续计算阶段识别过滤
  - **绝对禁止**将行李转运航班填入 flight_no 字段

典型场景示例：
> 旅客乘坐 CA1507（3月1日 PEK→SHA），行李未到。航司邮件通知："您的行李将搭乘 CA1515（3月3日）运抵上海。"
>
> 正确做法：
> - flight_no = "CA1507"（旅客实际乘坐的末段航班）
> - all_flights_found 中包含 CA1507（role_hint: "原航班/末段"）和 CA1515（role_hint: "行李转运航班"，source: "airline_email"）
>
> 错误做法（严重）：
> - flight_no = "CA1515" ← 这是行李转运航班，不是乘客航班，会导致延误时长计算严重偏小

### 行李路单号/行李号 vs 航班号（极易混淆）

航空公司的行李延误证明、PIR报告、邮件通知中经常出现**行李路单号**（Baggage Tag Number / Tracing Number），格式可能类似 "CA263192"、"MU123456" 等。**这些不是航班号，绝对禁止填入 flight_no 或 all_flights_found。**

区分方法：
- **航班号**：固定格式为 2位航空公司代码 + 1~4位数字（如 CA1507、MU5183、CZ380）
- **行李路单号**：数字部分通常超过4位（如 CA263192 有6位数字），或带有前缀/后缀（如 "BAG-CA1234"、"WT: CA12345"）
- 行李路单号常出现在 PIR 报告的 "Baggage Tag No." / "行李牌号码" / "Tracing Number" 字段中

### 联程/多段航班的触发航班判定（行李延误案件）

当旅客乘坐联程航班（多段航程）时，**行李延误的触发航班是旅客实际乘坐的末段航班的原计划航班**。

- 若联程航班的第一程正常、第二程取消/延误 → 第二程原航班为触发航班
- 若旅客在第二程改签 → 原第二程航班为触发航班（用于计算延误基准），改签后的航班用于 alternate 字段
- 末段航班的实际到达时间应以飞常准查询的**实际到达时间**为准，而非计划到达时间

### 机场三字码
延误证明、行程单、登机牌上的机场三字码（如 SVO、HGH、PVG、HKT 等）必须提取，用于时区换算和延误时长计算。

### 时间格式
统一输出 "YYYY-MM-DD HH:MM"

## 第二步：角色判定规则

根据 all_flights_found 中的信息，按以下规则判定每个航班的角色：

**原航班**（original）：
- 行程单/电子客票中列出的原定航班
- 多程行程中每一程的原定航班均需识别
- 若某程原航班取消/延误，该航班仍为原航班

**改签/替代航班**（alternate）：
- 原航班取消/延误后，承运人或客户重新购买的替代航班
- 登机牌上的航班若与行程单原航班不同，通常为改签航班
- 改签通知/短信中出现的新航班号

**保护航班**（protection）：
- 材料中明确出现"保护航班""protection flight"字样的航班
- 通常由航空公司在原航班取消时主动安排，客户可选择乘坐或自行改签

**注意**：
- 登机牌上的航班号 ≠ 一定是改签航班，需结合行程单对比判断
- 若行程单有两程，第一程正常到达、第二程取消，则第二程原航班为延误险的触发航班
- 若客户实际乘坐的航班（登机牌）与行程单原航班一致，则无改签
- **行程变动截图的角色判定（高频场景）**：航旅APP行程变动截图中，「原航班」区块的航班 = original（原航班），「行程变动后的新航班」/「新安排」区块的航班 = alternate（替代航班）。绝对禁止将「新航班」区块的航班号填入 flight_no（触发延误险的原航班）。flight_no 必须填「原航班」区块的航班号。

## 第三步：保护航班时间合理性校验

若存在保护航班，需校验：**客户实际乘坐的替代/改签航班起飞时间，必须晚于保护航班起飞时间**（客户放弃保护航班、自行选择更晚的替代方案，才符合"最早便利替代"原则）。

- 若替代航班时间 < 保护航班时间：`protection_check.result = "异常"` 并说明原因
- 若替代航班时间 ≥ 保护航班时间：`protection_check.result = "正常"`
- 若保护航班时间 unknown（材料未载明）：先记录保护航班号，后续由飞常准查询补全
